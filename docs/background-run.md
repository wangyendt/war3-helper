# 切换应用不自动暂停（单机，实验性）

在「窗口/控制」勾选 **切换应用不自动暂停**，选择「窗口化」或「无边框全屏」。
退出魔兽后，使用助手的「启动魔兽」重新启动；取消勾选也要通过助手重启一次，才能移除模块。
正在运行的游戏不会被热修改。设置保存到助手的 `config.json`，旧配置默认关闭。

这是单机便利功能，**联机或使用对战平台前请关闭并通过助手重启游戏**。
模块不检测游戏的单机/联机状态，也不解除联机暂停、修改游戏速度或发送游戏操作。
手动暂停菜单不在拦截范围内；切出游戏后，助手原有的改键仍停用。

## 范围与限制

- 独立于高帧率开关，可以单独使用，不需要下载。
- 版本白名单与内置版本一致：1.20e、1.21、1.22、1.23、1.24b、1.24e、1.25b、1.26、1.27a、1.27b。
  要求 `War3.exe` 和 `Game.dll` 构建号一致；这只是版本准入，不代表每版均已完成游戏实测。
- 不支持独占全屏：保留该模式的设备丢失/恢复流程，助手会提示切换启动模式。
- 依赖完整的 Miles 音频组件加载 MIX。禁用音频加载、平台特殊启动器或其他窗口插件可能导致不生效或冲突。
- 最小化时渲染和后台帧率仍由游戏/驱动决定，不保证后台 FPS；本功能不是后台输入工具。
- 如有画面、音频或切回异常，请关闭此功能并通过助手重启。

## 实现与文件管理

`native/BackgroundRun.cpp` 由 Miles 加载，检查版本及 `-window` 参数后启动工作线程。
仅寻找当前进程、类名为 `Warcraft III` 的窗口，通过线程级消息钩子在窗口所属线程安装子类过程。
它拦截 `WM_ACTIVATE/WA_INACTIVE` 和 `WM_ACTIVATEAPP/FALSE`，其他消息继续交给原窗口过程。
不会伪造 Windows 前台窗口，不调用 `SetForegroundWindow`，不拦截 `WM_KILLFOCUS`、按键抬起或菜单命令。
窗口销毁时清理子类状态，窗口重建后重新挂接；模块固定加载至游戏退出。

仅安装两个文件，不改动游戏 EXE/DLL、地图或存档：

| 文件 | 用途 |
|---|---|
| `War3HelperBackground.mix` | 内置 32 位窗口消息模块 |
| `.war3helper-background` | 管理版本与模块 SHA-256 |

启动前在与高帧率/版本切换共用的操作锁内执行安装、升级或移除。
同名未受管模块、用户修改内容和损坏的管理记录会被保留并报错。
文件写入失败时回滚；未受管的同名模块在选项关闭时也不会被删除。
切换版本不会删除这两个文件，下次通过助手启动时重新验证版本和设置。
高帧率模块及其管理文件不受影响。

## 验证记录（2026-10-23）

`build-test.ps1` 包含两层自动化测试：

1. C#：默认值、旧配置兼容、序列化、模式限制、安装/移除、冲突保护、损坏记录、缺失修复、失败回滚与高帧率独立性。
2. 原生 Win32 隐藏测试窗口：工作线程/窗口线程挂接、失活过滤、激活转发、失焦及 Alt 抬起转发、菜单命令转发、销毁与重建、Windows 前台归属不变。

这些测试不操作正在运行的魔兽。**尚未完成真实单机对局验证，因此当前标为实验性。**
实测验收应在每个目标版本分别检查：

- 单机地图让单位移动或计时触发器运行，Alt+Tab 10 秒后确认逻辑确实推进（不能仅看 FPS）。
- 在其他应用输入时，魔兽不抢焦点、不执行输入；切回后 Alt/Ctrl/Shift 不粘连。
- 手动暂停仍停住逻辑，恢复后正常运行；切回后画面、血条及声音正常。
- 关闭选项并通过助手重启，确认原版失焦暂停恢复。
- 分别测试 DirectX、OpenGL，以及高帧率开/关组合。
